# PRD Research Operator Workflow

This is the current Codex-priority, lowest-token operating model for running PRD Research.

The workflow is intentionally split so PMs keep the 1/2/3 decision gates while Codex handles deterministic local work, scoped web collection, and finalization support. Claude is an optional fallback only when Codex cannot complete a specific web collection batch.

## Code Words

Use these exact phrases with Codex:

- `PRD Research Prep`
- `PRD Research Collect`
- `PRD Research Finish`

## Canonical Paths

- Shared template:
  - `C:\Users\Sunco\Sunco Lighting\Product - Manny Tools\PRD Research\Working Tool Files\Templates\PRD_Research_Template.xlsx`
- Shared reports:
  - `C:\Users\Sunco\Sunco Lighting\Product - Manny Tools\PRD Research\Working Tool Files\Research Reports`
- Shared session root:
  - `C:\Users\Sunco\Sunco Lighting\Product - Manny Tools\PRD Research\Working Tool Files\output\research_sessions`

## Step 1. User

Fill the shared template.

Do not change the session folder manually.

## Step 2. Codex

Say:

```text
PRD Research Prep
```

Expected Codex behavior:

1. Read the canonical shared template.
2. Create a fresh session under the shared session root.
3. Seed Stackline, reference context, and any deterministic local/session data already available.
4. Inspect session status and narrow the next missing collection batch.
5. Return:
   - the session path
   - a short pending-collection summary
   - the exact Codex research task file for the next smallest useful batch

At this step, nothing should be published yet.
If Codex finds no remaining collection gaps, web collection is skipped and the run can go straight to finish.

## Step 3. Codex Research Collection

Say:

```text
PRD Research Collect
```

Use the full session-specific `1 - CODEX RESEARCH TASK.md` generated by Step 3, not only the code word itself.

Expected Codex behavior:

1. Preflight the exact mounted paths.
2. Read the Codex research task bundle first, then packet files only when needed.
3. Complete only the listed raw collection artifacts for that batch:
   - amazon
   - brick_and_mortar
   - brand_sites
4. Verify real URLs/products before writing raw artifacts.
5. Run the validation and manifest update commands listed in the task bundle.
6. Stop when that batch is complete or clearly blocked.

Repeat this step only if Codex says another batch is still needed.

Codex should not:

- patch repo code
- change templates
- rebuild reports
- publish outputs
- explore the whole session if the prompt already scopes exact rows/artifacts

If Codex cannot complete the web collection, use `2 - OPTIONAL CLAUDE FALLBACK PROMPT.md` for that exact batch only.

## Step 4. Codex

Say:

```text
PRD Research Finish
```

Expected Codex behavior:

1. Use the existing session.
2. Run normalize, price enrichment, analysis, row reports, combined workbook, manifest update.
3. Publish the completed workbook into `Research Reports`.
4. Return the final published workbook path.

## Why This Split Exists

This is the current lowest-token model:

- Codex handles deterministic local work, session narrowing, scoped raw collection, and finalization.
- Claude is used only as an optional fallback for external competitor collection Codex could not satisfy.

This avoids burning Claude tokens on:

- repo exploration
- path discovery
- session-wide planning
- broad task selection
- report rebuilding
- publishing

## Success Definition

A successful run means:

1. The shared template was processed.
2. Codex completed or explicitly blocked any missing raw competitor collection batches.
3. Codex finalized the session.
4. The completed workbook was published into `Research Reports`.
