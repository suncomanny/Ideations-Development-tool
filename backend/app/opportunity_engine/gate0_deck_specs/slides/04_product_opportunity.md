# Product Opportunity Slide

## Role

Create one slide for each Step 2 ideation row.

This slide answers: "What exactly is this product opportunity, what evidence supports it, and what should happen next?"

## Inputs

- Step 2 ideation row
- Step 2 source mapping row
- Step 3 row detail sheet, when available
- Step 3 Section F feature/certification signals
- Step 3 competitor tables
- Step 3 pricing section
- Step 3 PRD pre-fill section

## Layout

Use the product-slide structure from the team review deck:

- Top teal rule
- Large title at upper left
- Total SKU Count at upper right
- Product/reference image block on upper left
- Strategy block to the right of image
- Target Specs below strategy
- Gate 0 Read mini table on the upper right
- Product Variants table across the middle
- Comparable SKU Performance / Commercial Read table below variants
- Amazon Segment Competitor table
- Direct Segment Competitor table
- Source footnote
- Sunco footer

## Required Sections

### Title

Use a clean display title. If Step 2 has a long evidence-rich name, shorten it for the slide title while preserving the full name in the backend JSON.

### Strategy

Use Step 3 Overall Read first. If missing, use Step 2 source evidence or strategy.

### Target Specs

Use Step 2 explicit fields first, then Step 3 PRD pre-fill fields.

Preferred visible spec lines:

- Wattage
- CCT
- Dimming
- Voltage
- CRI
- Moisture
- Certifications

### Gate 0 Read

Show:

- Outlook
- Confidence
- Amazon G2

If Step 3 is missing, show `needs review` or `n/a`.

### Product Variants

Use one row per ideation/SKU permutation. If the current Step 2 workbook has only one row, show one row.

### Commercial Read

Use known Step 3 values. If no Step 3 report exists, show `N/A` rather than inventing metrics.

### Competitors

Use verified competitors first. If only inferred competitors exist, label them clearly.

## Guardrails

- Do not say a competitor match is apples-to-apples unless Step 3 verified it.
- Do not fabricate product images.
- Do not fabricate Stackline or revenue values.
- Do not overfill visible text boxes. Long detail belongs in backend JSON or speaker notes.
